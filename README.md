# 一点万象 Surge 自动签到

适用于 Surge iOS 的一点万象自动签到模块。首次打开一点万象签到页后记录签到所需参数，之后会通过普通网关请求持续刷新登录凭据。模块每天检查签到状态，仅在尚未签到时提交签到；也可通过策略组信息面板查看结果并手动触发。

## 安装

在 Surge iOS 中通过 URL 安装模块：

```text
https://raw.githubusercontent.com/unicom2zero/surge-mixc-signin/main/MixcSignIn.sgmodule
```

安装并启用后：

1. 确认 Surge 的 MitM 和脚本功能已开启，并已安装、信任 Surge CA 证书。
2. 打开一次“一点万象 -> 签到”页面，凭据刷新脚本会自动保存当前登录信息。
3. 打开 Surge 的“策略组”页面，找到“一点万象签到”面板。
4. 点击面板右侧的刷新按钮。出现“正在检查”通知后，等待面板显示签到结果。

首次成功记录后，如果以后重新登录一点万象，模块会从 `app.mixcapp.com` 下的请求中增量更新非空鉴权字段、Cookie 和相关请求头，不必再次进入签到页面。面板会显示凭据最后更新时间和来源接口，可用于确认新登录信息是否已被捕获。

从旧版本升级到模板版本 2 时，需要进入一次签到页面重建干净模板。完成这次迁移后，普通接口只会更新登录鉴权信息，不会再覆盖签到接口的 `mallNo`、`apiVersion` 等固定签名字段。

当前版本已在 Surge iOS 上验证：退出一点万象并重新登录后，无需进入签到页面，正常浏览 App 即可刷新凭据并通过面板完成签到检查。

## 修改签到时间

模块默认每天 `08:30` 自动签到。Surge iOS 的安装型模块目前不提供模块参数表，因此不会显示“参数设置”入口。

如需修改时间，可以使用仓库中对应时间的专用模块，或修改本地模块内“一点万象每日签到”的 `cronexp`。例如每天 `09:05` 为 `cronexp="5 9 * * *"`。远程模块更新会覆盖本地修改，长期使用建议创建专用时间版本。

### 验证定时触发

可临时安装 `MixcSignIn-Test.sgmodule`。它每 5 分钟运行一次，并在今日已经签到时发送“定时测试已触发”通知。确认收到通知后应立即停用或删除测试模块，避免不必要的频繁唤醒；正式模块仍保持每天 `08:30`。

## 面板状态

- `good`：今日已签到，或本次签到成功。
- `alert`：尚未获取登录凭据，需要重新打开一点万象签到页。
- `error`：登录可能失效、接口异常或网络请求失败，请根据面板信息处理。

面板还会显示凭据是否已记录，以及最近一次检查时间。

## 行为

- 默认每天 08:30 自动执行。
- 自动任务会先查询状态，已签到时不会重复提交。
- 策略组页面显示签到信息面板，点击右侧刷新按钮可立即检查并手动签到；触发后会先显示“正在检查”通知。
- 登录失效时会发送 Surge 通知；重新登录并在 App 中正常浏览一次即可刷新凭据。
- 登录 Token、Cookie 和设备信息只保存在 Surge `$persistentStore`，不会上传到 GitHub 或写入脚本文件。

## 常见问题

### 点击刷新没有反应

1. 在 Surge 的模块页面手动更新本模块。
2. 关闭再重新启用模块，然后返回策略组页面重试。
3. 确认 Surge 的脚本功能已经开启。
4. 查看“一点万象签到”的脚本日志；网络请求超过 12 秒会返回超时提示。

### 提示未获取登录凭据

确认 MitM 已开启、Surge CA 证书已安装并信任，然后登录一点万象并进入一次签到页面。模块会在网关请求发生时自动刷新凭据。

### 登录失效

当面板或通知提示鉴权失败、Token 失效等错误时，重新登录一点万象并在 App 中正常浏览一次，再点击面板刷新。只有首次安装、清除 Surge 数据或尚未保存 `mallNo` 时，才需要进入一次签到页面。

## 文件

- `MixcSignIn.sgmodule`：Surge 模块入口。
- `mixc_capture.js`：从一点万象请求中刷新登录鉴权信息，同时保护固定签到模板。
- `mixc_signin.js`：查询状态并执行签到。

该项目仅供个人学习与自动化使用，接口变化时可能需要更新。
